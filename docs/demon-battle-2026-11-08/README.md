# 마왕 본편 야차와 야차 승리 엔딩 — 임시 시뮬레이션

2026-11-08. 사용자가 3번 마왕 전투를 먼저 적용하고, 다음으로 2번 야차 승리 엔딩을 만들도록 순서를 변경했다.

## 기준과 범위

- 전투: https://app.notion.com/p/411648bf677880a8a548e37b47d3dffd
- 컷씬: https://app.notion.com/p/411648bf67788060b853e278b98bd354
- 앞부분의 오래된 6연격 요약 대신 상세 개편인 **추적 2연격 3회 → 발도술 1회**를 따른다.
- 기존 본편의 미용 실패 대사 → 공통 야차 iframe → 승패 결과에 연결했다. 폐기한 독립 마왕 게임이나 별도의 시험 야차를 되살린 것이 아니다.
- 필요한 체력 기준·그림자 구간·발판 전환은 적용했다. 4~6번의 전용 페이즈 전환 컷씬은 이번 범위가 아니며 현재 짧은 페이드와 문구만 쓴다. 7번 입장 뒷모습과 8번 전체 초상화 교체도 별도다.

## 전투

| 구간 | 규칙 |
|---|---|
| 1페이즈 | 5×5, 4개 행 검기와 십자/X → 반대 영역 폭파를 교대 |
| 2페이즈 | 전체 HP 70% 이하, 2개 행 레이저 3회 → 반사 레이저 1회 |
| 반사 | 오른쪽 가장자리 시작, 3~4개 고정 거울. 경로를 순서대로 예고. 마지막 거울만 클릭으로 돌리면 도착 시 마왕에게 반사·즉시 그로기 |
| 그림자 | HP 50% 이하에서 짧게 정지 후 위에서 본 5×5 발판과 실루엣. 마지막 거울 테두리는 유지 |
| 3페이즈 | HP 35% 미만. 각 타격의 예고 시작 때 플레이어 위치를 다시 고정. 십자 → X 2연격을 3회, 이후 발도술 |
| 20% 이하 | 원래 위치·크기의 가운데 3×3만 남기고 1타 세로열 / 2타 가로행 |
| 10% 미만 | 가운데 십자 5칸만 남기고 타격마다 현재 한 칸 추적 |
| 발도술 | 준비 중 현재 행 추적, 눈 반짝임 때 행 고정, 0.3초 뒤 타격. 파괴된 칸 제외 |
| 빈틈 | 기존 클릭 공격과 좌우 가위 긁기. 3페이즈 일반 공격 무력화 피해는 낮지만 0은 아님. 일반 공격으로 최종 처치 가능 |
| 패배 | 야차 재도전 또는 투구 미용부터 다시 하기. 패배 엔딩으로 넘어가지 않음 |

**임시 수치**는 src/combat/demon-engine.js의 DEMON_BATTLE_TUNING에 모았다. 총 HP 1000, 기본 공격 14, 긁기 16, 피격 16, 일반 예고 1350ms, 추적 예고 950ms, 회복 1450ms, 공격 복귀 430ms, 3페이즈 무력화 1이다. 그로기·클릭 간격은 기존 공통 조작에 맞췄다. 발도술 0.3초와 눈 반짝임 때 행을 고정하는 방식도 시험 설정이다. 확정 엑셀 수치로 취급하지 않는다.

페이즈가 한 번의 그로기로 건너뛰어지지 않도록 1페이즈 70%, 2페이즈 그림자 진입 50%, 3페이즈 진입 35% 미만 지점에서 피해를 잠시 멈추고 현재 빈틈 시간이 끝난 뒤 전환한다. 일반 공격 중이면 타격과 복귀가 끝난 뒤 전환한다. 파괴될 칸에 서 있었다면 가장 가까운 남은 칸으로 옮긴다. 이 연결 방식도 시뮬레이터 임시 보정이다.

Unity 원본 엑셀은 수정하지 않았다. 기존 페이즈 행 형식을 런타임 복사본에서 재사용하고, 현재 3×3용 편집기·Unity 미정 계약에 5×5 추적/반사 데이터를 억지로 저장하지 않았다. 마왕의 이 패턴들이 Excel 왕복과 Unity에서 실행된다고 설명하지 않는다.

## 리소스

제공된 1페이즈 PNG 스프라이트 시트와 2페이즈 레이저·중앙/측면 거울 시트를 사용한다. DemonKing3Pase.gif에서 0~16번 발도술 구간과 26/30번의 서로 다른 타격 자세를 분리했다. 회색 배경·베이지 표적·붉은 기준선의 정확한 색만 제외했으며 캐릭터의 흰색·회색은 보존했다.

BossMirror.unitypackage는 PNG가 아니라 메시와 머티리얼의 프리팹이다. 포함된 실제 삼각형을 웹용 정면/회전 이미지로 투영했다. 형태는 원본 메시를 사용하되 Unity 셰이더의 입체 조명까지 재현한 것은 아니다. 재생성 스크립트는 scripts/import-demon-battle-assets.cjs. 원본 파일을 변경하지 않는다.

3페이즈 타격 자세는 실제 목표 근처에 잠깐 나타나고 회복 때 원래 자리로 돌아온다. 승리 때 주저앉음·검 내려놓기와 주인공의 거절 동작은 기존 자세·흔들림·효과음으로 대체한 임시 연출이며 전용 완성 애니메이션이 아니다.

## 야차 승리 엔딩

전투 종료와 음악 정지 → 1.5초 여운 → “……내가 졌다.” 등 세 문장 → VICTORY YACHA → 고블린 모습의 마왕·부하·주인공이 있는 미용실. 부하가 새 마왕 자리를 제안하고, 주인공의 거절 뒤 원래 세계로 돌려보내기로 한다. 임시 단체사진을 남긴 뒤 초록 마법진·귀환 하늘·휴대폰·몬스타그램으로 이어진다.

미용 성공 엔딩의 다섯 손님 성공 후기 예시는 이번 엔딩에도 사용한다. 실제 기록과 보상은 바꾸지 않는다. 팀원 크레딧은 후기와 함께 끝나며, 그 뒤 마계일보의 정체 공개·국정 개선 기사 두 개와 주민 댓글이 나온다. 마지막은 고블린 마왕을 포함한 단체사진과 감사 문구다. ‘마지막 영업, 그리고 작별의 기념사진.’은 사진용 임시 캡션이다. 미용 성공 전용 왕의 예약 댓글이나 귀환 안내 게시글을 야차 분기에 섞지 않는다.

## 검증

- 관련 단위 검사: 전투 경계·추적 재포착·거울 성공/실패·정지·발판·공격 복귀·승패, 기존 공통 전투·마왕 미용·엔딩·승패 결과.
- 세 개의 결정적 난수 순서로 실제 엔진 이동/클릭/긁기 입력만 사용해 처음부터 승리까지 검사했다. HP를 주입하거나 줄이지 않았으며 모든 페이즈·그림자·발판 크기를 거쳤다. 사람의 난이도 평가나 수동 완주를 뜻하지 않는다.
- 브라우저: 실제 본편 마왕 방문 → 원래 미용 도구 화면에서 손질하지 않고 완료 → 실패 대사 → 야차 진입. 이후 HP/패턴 지점은 테스트 서버에서 설정하고 실제 WASD·클릭·긁기를 사용했다. 거울 그로기, 정지, 발판, 패배/두 재시도 선택, 승리 대사와 고블린 귀환, 기사·댓글·사진·감사 문구·재생/타이틀 복귀를 확인한다.
- 기존 미용 성공 엔딩 검사도 별도로 수행한다. 공개 코드에는 테스트 서버의 상태 변경 함수를 넣지 않는다.
- 실제 실행 캡처는 chromium/ 및 webkit/ 아래에 보관한다. phase3-frames.png와 sheets.png는 원본 리소스 분석용 조합이며 게임 실행 캡처가 아니다.
- Unity 실행이나 모든 손님의 전체 재플레이 검증은 아니다. 관련 검사만 선택해 배포한다.

로컬 확인 결과: 관련 65개 검사와 빌드 통과. Chromium 및 WebKit의 본편 진입·전투·야차 승리 엔딩 검사를 통과했고, 기존 미용 성공 엔딩 Chromium 검사도 통과했다. 공개 확인은 배포 후 동일 검사기의 --url 경로로 별도 기록한다.
