# 커피 유령·재등장 좀비 대사 전달 파일 누락 수정

확인한 전달본: 바탕화면 2026-11-02_19-53-52. 작업용 XLSM과 Unity용 XLSX 모두 저장 스냅샷의 대사 129행이며 커피 유령·재등장 좀비 그룹이 없다. 실제 셀 XML에서도 해당 인물/대사 키워드가 없다. 변경 이력에는 두 인물의 문장 수정이 기록되지 않았다. 원본 전달 파일은 수정하지 않았다.

원인: 두 손님은 workbookExcluded로 지정되어 있고, combatForWorkbook이 전투 편집기에 넘기기 전에 전용 대사·연결을 제외한다. 전체 프로젝트 JSON에는 남아도 기존 데이터테이블 ZIP에는 JSON이 포함되지 않아 상대방에게 전달되지 않았다. 앞선 대사 편집 추가에서 이 전달 경로를 해결하지 못한 결함이다.

수정:
- 통합판의 ZIP 및 폴더 버전 저장은 부모 편집기에서 최신 전체 프로젝트를 요청한다. 야차 화면에서 마지막에 편집한 데이터와 부모의 모든 대사/미용/분기 연결을 합쳐 야차차_통합프로젝트.json을 동봉한다. 요청 실패 시 불완전한 ZIP을 저장하지 않는다.
- XLSM/XLSX 스키마와 원본 VBA 계약은 그대로다. 두 특수 손님의 전용 데이터는 동봉한 JSON으로 보존한다. 이 변경은 Unity 테이블에 해당 대사가 새로 연동됐다는 뜻이 아니다.
- 개발실 프로젝트 불러오기는 새 ZIP과 JSON 모두 지원한다. JSON 없는 옛 ZIP은 복원했다고 가장하지 않고 안내 후 기존 작업본을 유지한다.
- 대사·미용·야차 편집 화면 상단에 프로젝트 파일 저장 버튼을 추가했다. 야차 화면에서 JSON을 직접 저장할 때도 현재 자식 편집기 내용을 먼저 수집한다.
- 파일 전달 방법을 ZIP 내부 안내·버전 정보·변경 이력·화면 안내에 적었다. 저장 권한은 유지한다.

복구 한계: 기존 ZIP에는 두 손님의 수정 문장 자체가 없으므로 그 파일만으로 복원할 수 없다. 작업자가 편집 탭을 열어 둔 상태라면 새로고침하거나 닫기 전에 개발실의 프로젝트 파일 저장으로 JSON을 받아야 한다. 작업자 PC의 실제 메모리/브라우저 저장본은 이 작업에서 확인하지 않았다.

검증: 관련 데이터·권한 검사 17개 통과. Chromium/WebKit에서 두 손님 문장·글자 효과 편집 → 직접 JSON 다운로드 → 야차 데이터 수정 → 실제 ZIP 다운로드 → 새 창 ZIP 불러오기를 확인했다. 전체 손님/분기 연결과 최신 야차 값이 일치한다. 폴더 저장은 메모리 파일 핸들 fixture에서 전체 JSON과 마지막 완료 표시 쓰기를 확인했다. 실제 Windows 폴더 선택기로 사용자의 폴더를 작성한 검증은 아니다. 로컬 검사 서버에서만 시험용 암호 검증 함수를 주입하며 공개 파일의 인증 코드와 실제 암호는 변경하지 않는다.

restored-dialogue.png는 실제 새 창에 ZIP을 불러온 뒤 재등장 좀비 수정 문장과 글자 효과가 복원된 검증 캡처다. 화면의 문장은 검사용이며 사용자가 받은 작업자의 문장을 복구한 화면이 아니다.
