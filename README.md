# 야차차 · 통합 플레이 & 개발실

공개 주소: **https://dante950.github.io/**

1일차 좀비 미용·야차 → 취객 야차와 소울 이야기 → 정산·몬스타그램 → 2일차 샌즈까지 플레이하는 통합 프로토타입입니다. 기존 전투 전용 HTML과는 별도입니다.

## 같은 주소로 업데이트하기

`main`에 변경을 올리면 GitHub Actions가 데이터를 검사하고 사이트를 다시 배포합니다. 별도의 HTML 파일을 이용자에게 전달하지 않습니다. 배포 성공 뒤 같은 주소에서 새로고침하면 됩니다.

최초 한 번, 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. 배포 진행은 저장소의 **Actions → Publish Yachacha**에서 확인합니다.

### 개발실에서 수치를 수정한 경우

1. 사이트의 개발자 시뮬레이터에서 수정합니다.
2. **내 브라우저에 저장 → 내 작업본으로 시험 플레이**로 확인합니다.
3. **프로젝트 파일 저장**으로 JSON을 보관합니다.
4. 아래 명령으로 공개 데이터를 반영한 뒤 변경분을 `main`에 올립니다.

```sh
node scripts/import-project.mjs "저장한 프로젝트.json"
npm run build
npm test
git add data/project.json
git commit -m "플레이 설정 업데이트"
git push origin main
```

사이트에서 누르는 저장 버튼은 **개인 브라우저 저장**입니다. 일반 방문자의 수정이 공개 본편을 덮어쓰지는 않습니다. 공개 본편은 항상 배포된 `data/project.json`을 사용합니다. 새 배포마다 개인 작업 공간은 새로 시작하므로 업데이트 전에 작업 중인 JSON을 저장하고, 필요하면 다시 불러오세요. 이전 저장값은 삭제하지 않습니다.

### 화면이나 게임 동작을 수정한 경우

`src/`를 수정하고 `npm run build`, `npm test`가 통과하면 `main`에 올립니다. Node.js 22 이상이 필요하며 빌드용 외부 패키지 설치는 필요하지 않습니다. `dist/`는 자동 생성 결과여서 Git에 올리지 않습니다.

## 구성

- `src/`: 메인 화면, 미용, 대사, 통합판 전투 코드
- `data/project.json`: 모든 방문자가 시작할 공개 설정
- `data/source.xlsx`, `data/source-authoring.xlsm`, `data/schema.json`: 기존 야차 엑셀 내보내기 틀과 규약
- `public/media/`: 제공된 캐릭터, 배경, 음악, 몬스타그램 이미지
- `vendor/`: 엑셀 처리를 위한 JSZip 및 라이선스
- `.github/workflows/pages.yml`: 검사와 GitHub Pages 자동 배포

야차 작업용·Unity용 엑셀 버전 저장 기능을 유지합니다. 미용 대사와 선택지 연결은 아래 엑셀 시트를 사용합니다. 미용 영역·배점·리소스·진행 설정은 프로젝트 JSON에 보관합니다. 브라우저에서 XLSM을 읽어도 VBA 매크로를 실행하지 않습니다.

## 웹 버전 0.13 · 엑셀로 연결하는 미용 대화

좀비와 샌즈의 형태·색·장식 요청은 `대사`와 `대화 그룹`에서 관리합니다. `미용 대사 연결` 시트는 손님과 단계마다 처음 부탁과 자세한 부탁의 그룹을 연결합니다. 처음 부탁의 마지막 문장 뒤 ‘네?’를 누르면 자세한 부탁 그룹을 읽고, ‘알겠습니다’를 누르면 손질을 시작합니다. 이미 들은 단계는 다시 듣기로만 재생하며, 되물었던 단계는 자세한 부탁을 재생합니다.

| 작업용 필드 | 자료형 | 의미 |
| --- | --- | --- |
| MonsterID | int | 손님 ID |
| Stage | string | cut: 형태 만들기, draw: 색·무늬, attach: 장식 |
| RequestGroupID | int | 처음 부탁의 DialogueGroup.GroupID |
| DetailGroupID | int | 네? 뒤 자세한 부탁의 DialogueGroup.GroupID |

행의 고유 키는 `MonsterID + Stage`입니다. 요청 그룹은 `순서대로 / 입력`으로 설정합니다. 같은 그룹의 Order는 연속 문장 순서이며 선택지 조건이 아닙니다. 예전 좀비의 두 번째 되묻기 그룹 80004는 보관하고 현재 연결에서는 제외했습니다.

1. 최신 작업용 XLSM의 대사와 미용 대사 연결을 수정하고 저장합니다.
2. 통합 개발실의 야차 편집기에서 그 엑셀을 불러옵니다.
3. 상단의 대사 또는 미용 화면으로 이동해 시험합니다. 엑셀에서 읽은 동일한 대사 행을 사용합니다.
4. 엑셀 버전 저장은 새 폴더에 XLSM/XLSX 한 쌍을 만듭니다. 웹에 공개하려면 별도로 프로젝트 JSON을 내보내 위 배포 절차를 진행합니다.

명령행 버전 저장은 이 통합판의 `node scripts/archive-version.mjs <수정한 엑셀> <변경 의도 TXT> [버전 저장 루트]`를 사용합니다. Playwright Chromium이 필요합니다. 기존 전투 전용 실험실과 그 변환기는 수정하지 않았습니다.

Unity용 시트명은 `SalonDialogue`, 헤더는 1행, 데이터는 2행부터입니다. 웹 시뮬레이터의 연결·검증과 엑셀 양방향 변환을 구현했으며, 실제 Unity의 C# 수신 클래스와 선택지 실행 연결은 프로그래머 확인 대상입니다. `npm run test:salon-dialogue`는 두 브라우저에서 선택·다시 듣기·여러 문장·엑셀 자료와 편집 전파를 확인합니다.

## 웹 버전 0.6 · 시작 손님 선택

본편 플레이와 개발실의 작업본 시험 플레이에서 좀비·취객·샌즈 중 시작 손님을 고릅니다. 실제 영업 순서에서 해당 손님의 위치로 시작해 뒤의 흐름은 그대로 이어집니다. 좀비는 1일차 첫 손님, 취객은 1일차 두 번째 손님(미용 없이 야차), 샌즈는 2일차 미용부터입니다.

각 시작은 0 G와 빈 영업 기록으로 시작하며, 건너뛴 손님의 보상·미용 결과·몬스타그램 게시글은 만들지 않습니다. 전투 수치와 엑셀·프로젝트 데이터는 변경하지 않았습니다.

## 웹 버전 0.5 · 전투 초기화와 브라우저 호환

본편과 개발실 전투는 통합 프로젝트의 전투 데이터로 시작합니다. 작업용·Unity용 엑셀 템플릿 해석은 버전 저장 시에만 진행합니다. 엑셀 해석 실패가 이미지 로딩과 화면 재생까지 중단시키지 않으며, 실패한 저장은 다시 준비할 수 있습니다. 새로 불러온 엑셀의 원본·버전 이력은 다음 버전 저장에 사용합니다. 이미지 로딩 실패 시 본편과 실험실 모두 재시도를 제공합니다.

Safari 18.3.1에서 엑셀 XML 오류 후 화면이 비어 있는 제보를 바탕으로 수정했습니다. Windows의 WebKit 18.2·26.5 및 Chromium으로 확인했으며, Linux WebKit에서 내장 Unity 엑셀의 시트 연결 XML 앞에 남은 U+FEFF(BOM) 때문에 같은 XML 오류가 발생하는 것을 확인했습니다. ZIP에서 이미 문자로 풀린 XML은 맨 앞 BOM 하나만 제거한 뒤 해석하며, 본문의 문자나 원본 파일은 바꾸지 않습니다. 실제 Mac Safari 18.3.1 기기의 재확인은 별도입니다. XML 실패를 강제로 주입한 상태의 전투 시작, 불러오기 후 전투·쌍 엑셀 저장, VBA 보존, 리소스 로딩 재시도와 방문자 잠금을 검사합니다. 전투 수치·대사·엑셀 원본은 변경하지 않았습니다.

브라우저 검사는 `npm install`, `npx playwright install chromium webkit` 후 `npm run build && npm run test:browser`로 실행합니다. Linux에서는 브라우저 설치 시 `--with-deps`를 사용합니다. 자동 배포에서도 이 검사를 통과해야 공개됩니다. Playwright는 검사 전용이며 웹 산출물에 포함되지 않습니다.

## 웹 버전 0.4 · 저장 기능 잠금

처음 방문하거나 새로고침하면 저장 기능이 잠깁니다. 회색 저장·불러오기·내보내기 버튼을 누르면 비밀번호 창이 열립니다. 비밀번호를 확인하면 미용·전투·대사 실험실의 관련 기능이 함께 열리고, 상단 **다시 잠그기**로 잠글 수 있습니다. 잠금 해제는 현재 열린 페이지에서만 최대 8시간 유지하며 비밀번호나 해제 여부를 브라우저 저장소에 보관하지 않습니다.

이 기능은 공개 정적 시뮬레이터의 일반적인 사용을 제한하는 편의 잠금입니다. 서버 인증, 계정별 권한, 공개 데이터의 복제 방지 기능이 아닙니다. 기존 공개 파일과 저장소 이력도 비공개로 바뀌지 않습니다. 비밀번호를 아는 사람은 같은 기능을 사용할 수 있습니다. GitHub 로그인이나 외부 인증 서버를 사용하지 않습니다.

실제 비밀번호는 코드·문서·테스트에 기록하지 않습니다. `src/owner-access.js`에는 PBKDF2-SHA256 확인값만 둡니다. 저장은 계속 개인 브라우저/다운로드에만 적용되며 공개 데이터 배포에는 기존 GitHub 저장소 권한이 필요합니다. 게임·전투·엑셀 데이터 값은 변경하지 않았습니다.

통합판 0.2의 게임 내용과 데이터를 웹 배포 구조로 옮겼습니다. 이미지·음악 112개를 파일로 분리하고 변경된 파일 이름에 버전 해시를 붙입니다. 네트워크 오류 시 재시도 화면을 표시하며, 공개 본편과 개인 개발실 설정을 구분합니다. 전투 수치 변경은 없습니다.

## 2026-10-15 · 하루 마감 연출실 1

별도 입구 `closing.html`에서 새 중간시연 기획의 정산을 시험합니다. 1일차 취준좀비·샌즈, 2일차 마왕 부하의 결과를 대입하고, 영업 종료 → 몬스타그램 후기 → 팔로워 재연 → 아래에서 위로 채워지는 별 → 다음 날 달력 → 분홍 미용실 감상까지 진행합니다. 기존 본편의 일정·프로젝트 JSON·Excel 데이터는 이 연출실과 별개입니다.

DAY 3는 조작 없는 감상 장면입니다.

화면·진행은 `src/closing`, 빌드 연결은 `scripts/build.mjs`, 보상 규칙 검사는 `tests/closing.test.mjs`, Chromium·WebKit UI 검사는 `scripts/check-closing.mjs`에 있습니다. `npm run build`, `npm test`, `npm run test:closing`으로 확인합니다.

제공된 정산 PPTX의 기본·분홍 미용실 원본, 기존 좀비 후기와 캐릭터 리소스를 사용했습니다. 분홍 배경에 포함된 임시 말풍선 위에는 1스타 안내 UI를 배치했습니다. 마왕 부하 완성 원화는 미제공으로 임시 실루엣을 표시하며, 후기 문장·연출 시간은 시험용입니다. 데이브 더 다이버의 영업 마감·카운트업 리듬을 참고했으며 해당 게임의 로고·음원·정산 패널은 복사하지 않았습니다. 효과음은 브라우저에서 합성합니다. 글꼴은 [Galmuri11 v2.40.3](https://github.com/quiple/galmuri), SIL OFL 1.1이며 `public/media/closing-font-LICENSE.txt`에 전문을 포함합니다. 실제 Unity 구현이나 기존 통합 본편에 정산이 연결됐다는 의미는 아닙니다.

### 연출실 1.1 · 미용실 UI와 읽는 속도

피드백에 따라 큰 영업 안내 카드와 분리된 상단 일차·미용실명·팔로워 표시를 제거했습니다. 왼쪽 위에는 사용자가 추가 제공한 `UI_Main_Clock`, `UI_Main_Clock_Morning`, `UI_Main_Clock_Night`, `UI_Main_Clockcenter`, `UI_Main_Clockhands` 원본 PNG 5개로 시계·달력·바버폴과 별·팔로워를 모았습니다. 원본 픽셀은 보존하고 화면에서 3배로 확대했으며, 프레임의 동전 표시는 별로 덮었습니다. `NEW/T_Mimic.png` 캐셔를 별도 도트 이미지로 배치하고 영업 종료 말풍선은 캐셔 위로 올려 겹치지 않게 했습니다.

다음 후기는 실제 피드 전체가 1.8초에 걸쳐 위로 이동하며, 이전 게시글과 다음 게시글이 이동 중 함께 보입니다. 이동이 끝난 다음에 새 손님의 수치 증가가 시작됩니다. 기본 팔로워·별 증가 시간은 2.3초에서 6초로 늘리고 초반에 대부분의 값이 올라가던 곡선을 완만하게 바꿨습니다. 페이지에서 시험할 핵심 스크롤·카운트는 OS 모션 감소 설정이 켜져 있어도 순간 전환하지 않으며, 장식 입자·반복 움직임만 줄입니다. 사용자가 선택한 연출 속도는 계속 적용됩니다.

정상 모션·1배속 브라우저 검사는 중간 수치와 6초 유지, 스크롤 중간 위치·두 게시글 동시 노출, 스크롤이 끝나기 전 다음 보상을 표시하지 않는 동작, 캐셔와 말풍선의 비겹침을 확인합니다. 마지막 화면의 값만 일치하는 검사와 구분합니다. 실제 보상값·일차·제안과 강제 야차의 결과 규칙은 변경하지 않았습니다.
